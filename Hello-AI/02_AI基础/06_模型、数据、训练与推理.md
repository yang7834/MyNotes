## 1. 核心概念与背景

- **模型（Model）**：一套会计算的规则。
- **数据（Data）**：模型看过的材料。
- **训练（Training）**：把规则调出来。
- **推理（Inference）**：训练好的模型真正开始回答问题。
- 数据可以是文本、代码、图片、音频；训练包含预测、算误差、调参数；推理是把新输入变成回答。
- 本章解决很多底层问题：为什么不同模型回答差很多？为什么参数多体验未必好？为什么公司总说微调？为什么训练贵且按 token 收费？为什么模型会幻觉或对新事件不知道？
- 类比：模型=学生的大脑结构，数据=教材、题库和错题本，训练=刷题、判错、调整思路，推理=考试现场答题。

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/model-data-training_mermaid_0_9b28aad3.svg)

- 两个阶段容易混：
  - 训练阶段：模型还在学习，参数会被更新。
  - 推理阶段：模型已训练好，参数通常固定，只是根据输入计算输出。
- 因此「训练一个模型」和「调用一个模型」完全不是一回事。

## 2. 模型：一套会计算的复杂规则

- 模型是一个数学函数：输入 → 模型 → 输出。
- 传统程序是人写规则，机器学习让模型从数据里调规律。
- **Transformer** 架构出自 2017 年论文 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。它基于注意力机制，去掉循环和卷积结构，更适合并行训练和大规模扩展。GPT、Claude、LLaMA、DeepSeek、Gemini 都基于它。
- **参数（Parameter）**：模型内部的旋钮。训练前随机，训练中调整，训练后变成能力。

参数规模对比：

| 模型 | 参数规模 | 适合理解成什么 |
| --- | --- | --- |
| 小模型 | 几亿到几十亿参数 | 一本薄教材，够做轻量任务 |
| 中型模型 | 数十亿到上百亿参数 | 一个专业书架，能处理常见复杂任务 |
| 大模型 | 数百亿到数千亿参数 | 一座图书馆，容量更大，但维护成本也更高 |

- 真实例子：
  - GPT-3 论文公开了 **175B** 参数，展示 few-shot learning。
  - Llama 3 有 **8B** 和 **70B** 两种规模，预训练数据超过 **15T tokens**。
  - DeepSeek-V3 是 MoE，总参数 **671B**，激活约 **37B**，预训练使用 **14.8T tokens**。
- [Chinchilla 论文](https://arxiv.org/abs/2203.15556) 提醒：很多大模型卡住，往往缺足够多的训练数据，而不是缺参数。70B 的 Chinchilla 在多项任务上超过 280B 的 Gopher。
- 记法：参数像脑容量，数据像读过的材料，训练像学习方法。

## 3. 数据：模型真正吃进去的东西

- 数据是模型学习的原料。大语言模型以文本和代码为主，多模态还包括图片、音频、视频。数据会被处理成 token、图像块、音频特征等。

数据类型表格：

| 数据类型 | 例子 | 常见用途 |
| --- | --- | --- |
| 文本 | 网页、书籍、百科、新闻、论坛 | 学语言、常识、写作、问答 |
| 代码 | GitHub 代码、文档、Issue | 学编程、补全、调试 |
| 图片 | 照片、截图、扫描件、图表 | OCR、图像理解、文生图 |
| 音频 | 录音、播客、会议音频 | 语音识别、语音对话 |
| 人类标注数据 | 人写的理想回答、偏好排序 | 让模型更会对话、更安全 |

- 数据三层次：**规模**、**质量**、**覆盖**。
- Llama 3 用超过 15T tokens 预训练，微调数据包含公开 instruction datasets 和超过 10M human-annotated examples。DeepSeek-V3 预训练 14.8T tokens。
- 数据大不等于干净，可能混有重复网页、低质量内容、错误答案、偏见、广告、过期信息、测试集泄漏。
- **数据清洗（Data Cleaning）**：去重、过滤低质量、删除违法有害内容、语言识别分类、处理版权、挑选高质量样本。
- 现实：数据比 GPU 更难复制，真正高质量、干净、可授权的数据难获取。
- **数据污染（Data Contamination）**：训练数据混入评测题或测试集答案，导致榜单虚高。看 benchmark 时要问是否被污染。
- **模型崩塌（Model Collapse）**：来自论文 [The Curse of Recursion](https://arxiv.org/abs/2305.17493)。模型用自己生成的内容训练会产生不可逆缺陷，长尾消失。短期合成数据有用，长期需真实数据校准。

## 4. 训练：预测、犯错、改参数

- 训练是让模型从数据中学习规律并调参。语言模型基础任务：预测下一个 token。

示例：

```
text 深圳今天的天气很
```

- 模型猜「热」「好」「潮湿」，对比真实文本，算误差，通过反向传播（Backpropagation）调整参数。

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/model-data-training_mermaid_1_82379a86.svg)

- GPT-4 技术报告：预训练目标是预测文档中的下一个 token，但未公开参数量、训练 token 数、数据和算力。

训练成本表：

| 成本 | 花在哪里 |
| --- | --- |
| 算力 | 大量 GPU/TPU 长时间计算 |
| 数据 | 采集、清洗、授权、标注、筛选 |
| 工程 | 分布式训练、故障恢复、监控、调参 |

- DeepSeek-V3 完整训练用了约 **2.788M H800 GPU hours**。
- 训练会遇到显存不够、通信瓶颈、不稳定等问题，不是按一下开始。

## 5. 预训练、后训练、微调：三件事别混

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/model-data-training_mermaid_2_4ab9ea02.svg)

- **预训练（Pre-training）**：通识教育，读海量文本、代码、多模态材料，得到基座模型（Base Model）。基座模型只会续写，不一定适合聊天。
- **监督微调（SFT）**：人类准备「指令 → 理想回答」样本，让模型学会听指令。
- **RLHF**（Reinforcement Learning from Human Feedback）：人类偏好排序训练。InstructGPT 论文经典流程：
  1. 收集标注员和 API 的 prompt；
  2. 标注员写理想回答，做 SFT；
  3. 同一个问题生成多个回答，人类排序；
  4. 用偏好排序训练。
  InstructGPT 1.3B 输出优于 175B GPT-3，说明指令遵循不能只堆参数。
- **DPO**（Direct Preference Optimization）：更简单的偏好优化，来自 [DPO 论文](https://arxiv.org/abs/2305.18290)，直接把偏好数据用于优化，免去奖励模型 + 强化学习。
- **LoRA**（Low-Rank Adaptation）：冻结原权重，只训练额外小矩阵。论文显示对 GPT-3 175B，可训练参数减少 **10,000 倍**，GPU 显存需求降低 **3 倍**。
- **QLoRA**：4-bit 量化 + LoRA，65B 模型可微调到单张 48GB GPU。普通团队也能微调大模型。

## 6. 推理：模型真正开始干活

- 推理是训练好的模型接收新输入并生成输出。例如 ChatGPT 等应用每生成一个字都是推理。

训练 vs 推理表：

| 维度 | 训练 | 推理 |
| --- | --- | --- |
| 目标 | 学习规律，调整参数 | 使用规律，生成结果 |
| 参数 | 会更新 | 通常固定 |
| 成本 | 一次投入巨大 | 按调用持续消耗 |
| 时间尺度 | 几天到几个月 | 毫秒到分钟 |
| 典型场景 | 训练 GPT、LLaMA、DeepSeek | 用户聊天、代码补全、RAG 问答 |

- 大语言模型逐 token 生成，不会一次性写完整篇。

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/model-data-training_mermaid_3_a6aebdcc.svg)

- 影响：回答越长耗时越久、输出可能中途跑偏、上下文越长成本越高、复杂推理题写中间步骤更稳。
- [Chain-of-Thought 论文](https://arxiv.org/abs/2201.11903)：在 prompt 里给带中间推理步骤的示例，显著提升算术、常识、符号推理表现。
- 推理成本来源：模型大、上下文长、输出长、并发高。
- **KV Cache**：缓存前文 Key/Value，避免重复计算，但增加显存。
- [vLLM / PagedAttention 论文](https://arxiv.org/abs/2309.06180)：借鉴操作系统分页，提升吞吐量 **2–4 倍**。
- **投机解码（Speculative Decoding）**：小模型草拟，大模型并行验证，Chinchilla 70B 上加速 **2–2.5 倍**。

## 7. 最小示例：教一个模型认识「猫」

假设做一个识别猫的模型。

| 环节 | 在这个例子里是什么 |
| --- | --- |
| 模型 | 一个能处理图片的神经网络 |
| 数据 | 很多猫、狗、兔子、鸟的照片 |
| 标签 | 每张图对应的答案，比如「猫」或「狗」 |
| 训练 | 模型猜答案，猜错就调参数 |
| 推理 | 看到一张新照片，判断里面是不是猫 |

- 若训练数据全是橘猫，模型会以为「橘色」是关键特征，看到黑猫会犹豫——数据偏见。
- 错误标签会带歪模型——数据质量问题。
- 测试图已在训练集中，分数好看但真实表现一般——数据污染。
- 模型能力背后是数据、训练目标、工程约束和评估方式。

## 8. 一个大模型从训练到上线，大概会经历什么

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/model-data-training_mermaid_4_3dc94d45.svg)

- 真实流程更复杂，但此图足够识别行业新闻话术。
- 「我们训练了一个千亿模型」：问数据、训练成本、评测、推理成本。
- 「我们基于 LLaMA 微调」：问微调数据、任务范围、安全边界。
- 「我们做了行业大模型」：问行业高质量数据，是否只是套壳 RAG。
- 「我们模型榜单第一」：问 benchmark 有没有污染，真实场景验证。

## 9. 训练、微调、RAG、Prompt，到底该选哪个

| 需求 | 更常见的做法 | 原因 |
| --- | --- | --- |
| 想让回答风格固定 | Prompt / 系统提示词 | 成本低，改起来快 |
| 想让模型查公司知识库 | RAG | 知识经常变，不适合写死进参数 |
| 想让模型稳定执行某类格式任务 | SFT / LoRA 微调 | 有大量高质量样本时效果更稳 |
| 想让模型学会全新领域能力 | 继续预训练 + 微调 | 成本高，需要大量数据和算力 |
| 想降低推理成本 | 量化 / 蒸馏 / 小模型 | 面向部署和成本控制 |

- **RAG**（Retrieval-Augmented Generation）：推理时检索外部资料塞给模型，不需要所有知识重新训练进参数。
- 企业文档、客服 FAQ 等优先用 RAG；微调更适合固定输出格式、风格、任务步骤。

## 10. 常见误区

- 误区 1：参数越多，模型一定越好——还取决于数据、训练配比等。Chinchilla 70B 超过 280B Gopher。
- 误区 2：数据越多越好——前提是质量过关。
- 误区 3：微调可以解决所有问题——基座模型不会的，微调变不出来。
- 误区 4：模型训练完就永远知道最新知识——知识截止时间存在，Llama 3 8B 到 2023 年 3 月，70B 到 2023 年 12 月。
- 误区 5：推理只是调用一下，不怎么花钱——加载参数、上下文、KV Cache、逐 token 生成，长期烧钱。
- 误区 6：榜单分高就等于真实好用——可能污染、题型固定、真实业务有延迟成本安全等。

## 11. 使用和开发时的安全边界

- 不要把敏感数据随手拿去训练或微调，一旦进入训练集很难彻底删除。
- 上传数据前看清服务条款（API 数据是否用于训练）。
- 别把模型输出直接当事实，可能幻觉。
- 自动化执行要加确认，尤其工具调用、发邮件、删文件等。
- 商业使用注意版权和授权。

## 12. 练习题 / 小实验

练习 1：判断是哪一层的问题
- 模型回答公司旧制度：更像知识更新问题，可考虑 RAG 或重新训练。
- 模型数学题经常算错：基座能力和推理策略问题。
- 固定格式输出不稳定：可考虑 Prompt、SFT 或结构化输出约束。
- 同一个模型在短回答时很快，长报告生成很慢：推理阶段输出 token 多、上下文长，成本和延迟上升。

练习 2：选方案
- 每周更新的产品文档，优先 RAG。因为文档频繁更新，适合推理时检索最新资料；微调会把某一时刻知识写进参数，更新成本高，还容易保留旧答案。

练习 3：改写一个更稳的需求
- 「帮我训练一个公司内部大模型」没有说明目标、数据、预算、风险边界和验收方式。
- 建议改成：「我们想做一个内部知识库问答助手，资料包括产品文档、FAQ 和售后案例，每周更新。请先判断用 RAG、微调还是二者结合更合适。回答时需要比较成本、更新难度、数据安全和上线周期，并给出最小可行方案。」

## AI总结

本文用「模型、数据、训练、推理」四个概念串起现代大模型的核心链路。模型是数学函数与参数集合；数据决定模型能学到什么；训练通过预测、误差、调参得到能力；推理是训练后的模型逐 token 生成输出。文中详细区分了预训练、SFT、RLHF/DPO、LoRA 微调，也强调了数据质量、污染与模型崩塌风险，并讨论了 RAG 与微调的选择、常见误区和安全边界。适合 AI 初学者建立底层认知。
