## 1. 这章解决什么问题

很多人第一次接触 AI，是从聊天窗口开始的。但当遇到“上传图片分析”“语音转文字”“文生图”“自动加字幕”等产品时，会发现它们底层都在处理同一个问题：**怎样把不同形式的信息，变成模型能理解、能计算、能生成的东西。**

读完这一页，你应该能分清：

- 多模态 AI 到底在处理什么；
- 文本、图片、语音、视频进入模型前会经历什么；
- 看图问答、文生图、语音识别、视频理解分别属于哪类任务；
- 为什么多模态模型越来越像一个「统一入口」；
- 多模态能力有哪些边界，哪些场景必须人工复核。

## 2. 先认识「模态」

**模态（Modality）** 指信息的表现形式。AI 处理信息时，会遇到不同模态。常见模态、典型输入和任务如下：

| 模态 | 典型输入 | 常见任务 |
| --- | --- | --- |
| 文本 | 文章、聊天记录、代码、表格 | 总结、翻译、问答、写作、代码生成 |
| 图片 | 照片、截图、海报、医学影像 | 识别物体、读图、OCR、图像生成 |
| 语音 | 录音、会议音频、播客 | 语音识别、语音合成、说话人识别 |
| 视频 | 电影片段、监控、课程录像 | 视频理解、动作识别、自动剪辑、字幕生成 |

**多模态 AI（Multimodal AI）** 就是能处理两种或更多模态的 AI 系统。例如：

- 上传冰箱照片，让模型判断能做什么菜；
- 发一段会议录音，让模型整理纪要；
- 给模型网页截图，指出按钮设计哪里别扭；
- 输入「赛博朋克风格的猫」，生成图片；
- 看短视频后问“动作发生在第几秒”。

## 3. 一张图看懂多模态流程

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/multimodal-ai_mermaid_0_162fdb6a.svg)

核心一句话：**不同模态进入模型前，都会先被转换成模型能计算的数字表示。**

- 文本被切为 Token；
- 图片被拆成图像块；
- 语音被转成声学特征；
- 视频被拆成帧，再加上声音和时间顺序。

**编码器（Encoder）** 是将原始信息转换成向量表示的模块。图像编码器负责把图片变成向量，音频编码器负责把声音变成向量，文本编码器负责把文字变成向量。模型真正处理的是这些表示，它从未直接“看到”图片或“听到”声音。

## 4. 文本：LLM 的主战场

文本是目前最成熟、最常见的 AI 输入。输入一句话，模型先切 Token，再通过 Embedding 变成向量（详见 [Token、Embedding 与上下文窗口](https://unclecheng-li.github.io/Hello-AI/basics/token-embedding-context/)）。

文本 AI 擅长总结、改写、提取信息、写代码、分析材料、生成草稿。信息密度高、结构清楚，但缺点是很多现实问题不长成文字，例如报错截图、访谈录音、监控视频。

## 5. 图片：让模型「看见」东西

图片进入模型时通常被拆成许多小块。常见词 **OCR（Optical Character Recognition，光学字符识别）** 指从图片中识别文字。

图片 AI 常见任务：

| 任务 | 例子 | 成熟度 |
| --- | --- | --- |
| 图像分类 | 判断一张图片是猫、狗还是汽车 | 比较成熟 |
| 目标检测 | 找出图里的行人、车辆、路牌 | 比较成熟，但复杂场景会错 |
| OCR | 从截图、票据、扫描件里读出文字 | 清晰文字较成熟，小字和斜拍容易错 |
| 看图问答 | 上传一张图，问「这张图哪里有问题」 | 可用，但要防幻觉 |
| 图像生成 | 根据文字生成图片，或改风格 | 创意场景可用，细节要审 |

实用场景：把代码报错截图发给模型，模型先 OCR 读取文字，再理解错误信息。

小例子：一张菜单照片，模型可以识别英文、翻译中文、按口味推荐、提醒过敏原、估算价格。但过敏原、价格等信息如果菜单没写清楚，模型可能猜。OpenAI 视觉模型文档明确提醒：模型可能在小字、旋转文字、非拉丁文字、图表、精确空间定位、计数、全景图、鱼眼图像和专业医学图像上出错，不能用于医学建议。

## 6. 语音：从声音到文字，再从文字到声音

语音 AI 有两条路线：

- **语音识别（ASR）**：把声音转成文字。例子：会议录音转写、视频自动字幕、语音输入法、客服质检。OpenAI 的 Whisper 是典型 ASR 系统，使用 68 万小时多语言、多任务监督数据训练，支持转写、语言识别、短语级时间戳以及英译。
- **语音合成（TTS）**：把文字读成声音。例子：有声书、导航播报、数字人配音、AI 客服。

语音难点：口音、背景噪声、多人同时说话、停顿、语气、笑声。

小例子：会议纪要流程可能有三步：语音转文字 → 区分发言人和议题 → 总结结论和待办。第一步听错关键词，后面会偏。例如“下周三上线”被识别成“下周上线”。

传统语音助手是三段式：ASR → 语言模型 → TTS。GPT-4o 则把文本、视觉和音频放进一个端到端模型里，音频平均响应约 320 毫秒，最快 232 毫秒。

## 7. 视频：图片、声音和时间一起处理

视频是一连串图像，加上声音、字幕、镜头切换和时间顺序。

任务：自动加字幕、找高光片段、动作识别、课程知识点分析、文生视频、风格化处理。

视频理解难在“时间”：需要知道顺序、因果、谁先谁后。

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/multimodal-ai_mermaid_1_1ab8559c.svg)

长视频分析比文章总结更慢、更贵。视频生成方面，Sora 支持最高 1080p、最长 20 秒视频，支持 remix、blend、storyboard、延展和补帧。Google Veo 支持文生视频、图生视频、音频生成、角色一致性、摄像机控制、首尾帧控制、1080p/4K 输出。但视频生成尚未完全稳定，画面一致性、物理关系、口型同步、版权和肖像风险仍需人工审核。

## 8. 多模态模型和 LLM 是什么关系

LLM 擅长处理文字；多模态模型在旁边加上“看图”“听声音”“处理视频”的能力，再接到语言模型里，让模型用文字回答。

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/multimodal-ai_mermaid_2_fd817e8a.svg)

可理解为一个团队：图像编码器看图，语音模块听声音，语言模型组织答案，产品层包装成功能。截至 2026 年，GPT-4o 支持文本、图像、音频交互；Gemini 系列强调原生多模态；Claude 支持图像理解。具体能力以官方说明为准。

## 9. 关键演进：从「拼接」到「原生多模态」

![Mermaid Diagram](https://unclecheng-li.github.io/Hello-AI/assets/mermaid/multimodal-ai_mermaid_3_6ef7daa1.svg)

拼接系统每步都会丢信息：语音转文字丢语气，抽关键帧丢动作过程，OCR 错误影响推理，多模型串联增加延迟。原生多模态让文字、图像、声音、视频在同一个上下文里共同参与理解和生成。

关键节点表：

| 时间 | 节点 | 为什么重要 |
| --- | --- | --- |
| 2021 | [CLIP](https://arxiv.org/abs/2103.00020) | OpenAI 用 4 亿图文对训练，使图片和文字进入同一语义空间，证明自然语言可作为视觉任务的通用接口。 |
| 2022 | [Flamingo](https://deepmind.google/discover/blog/tackling-multiple-tasks-with-a-single-visual-language-model/) | DeepMind 让模型接收交错的图片、视频和文本 prompt，只用少量示例完成新任务。 |
| 2023 | [GPT-4V](https://openai.com/index/gpt-4v-system-card/) | GPT-4 获得图像输入能力，带来新的图像安全评估问题。 |
| 2023 | [Gemini](https://arxiv.org/abs/2312.11805) | Google 将 Gemini 定义为原生多模态模型家族，面向文本、代码、图像、音频和视频。 |
| 2024 | [GPT-4o](https://openai.com/index/hello-gpt-4o/) | OpenAI 将文本、视觉、音频放进端到端模型，降低实时语音交互延迟。 |
| 2024-2025 | [Sora](https://openai.com/index/sora-system-card/) / [Veo](https://deepmind.google/models/veo/) | 视频生成从文生视频走向图生视频、视频编辑、音画同步和更细控制。 |
| 2025 以后 | [Project Astra](https://deepmind.google/models/project-astra/) / [Operator](https://openai.com/index/introducing-operator/) 类 Agent | 多模态能力进入 Agent：结合记忆、工具和界面控制去行动。 |

## 10. 能力成熟度地图

不同多模态能力成熟度差别很大：

| 能力 | 现在大概到什么程度 | 最容易踩的坑 |
| --- | --- | --- |
| 文本总结和问答 | 很成熟 | 材料不全时会补脑 |
| 清晰图片 OCR | 比较成熟 | 小字、斜拍、反光、复杂排版容易错 |
| 看图问答 | 可用 | 会把猜测说得像事实 |
| 语音转文字 | 比较成熟 | 口音、噪声、多人重叠、专有名词会影响结果 |
| 文字转语音 | 可用 | 授权声音、AI 声音披露、情绪自然度要注意 |
| 视频理解 | 正在快速进步 | 时间顺序、因果关系、长视频一致性更难 |
| 文生图 / 图生图 | 创意草图很强 | 手、文字、品牌标识、真实人物肖像要审 |
| 文生视频 / 图生视频 | 很适合概念片和分镜 | 物理一致性、人物连续性、口型、版权风险仍明显 |
| 多模态 Agent | 早期但潜力大 | 看错界面、点错按钮、越权操作都可能带来真实后果 |

更稳的做法：让模型做草稿、辅助理解和检索，关键结果由人复核。

## 11. 多模态 RAG：让图片和图表也能被检索

普通 RAG 主要检索文字。如果答案藏在 PDF 的流程图、截图、扫描表单、架构图里，就需要多模态 RAG。

常见做法：

1. 从 PDF、PPT、Word 提取正文；
2. 提取文档中的图片、图表、截图；
3. 用视觉模型给图片生成文字描述；
4. 将正文和图片描述一起向量化；
5. 用户提问时同时检索文本和图片描述；
6. 模型基于检索结果回答并给出来源。

Microsoft Azure AI Search 的多模态搜索文档提到，可将图片生成自然语言描述，放进同一套搜索和 RAG 管道。

## 12. 多模态 AI 的常见误区

- **误区 1**：模型能看图，就等于理解现实世界。模型看到的是像素和训练数据模式，不是生活经验。
- **误区 2**：图片里有文字就一定能读准。小字、斜拍、反光、遮挡、手写字都会影响识别。
- **误区 3**：语音转文字后后面就不会错。转写错字、漏字、说话人混淆会影响后续判断。
- **误区 4**：视频生成已完全替代拍摄。涉及真实人物、品牌素材、产品细节、事实场景时需审核。
- **误区 5**：多模态 Agent 看得见界面就能操作对。误读、点错按钮、遗漏确认都可能，涉及付款、发邮件、删文件、改权限必须人工确认。

## 13. 最小示例：同一个需求，四种模态怎么处理

假设目标是“了解一台咖啡机怎么用”，不同材料对应不同处理方式：

| 你给 AI 的材料 | AI 可以怎么帮你 | 风险点 |
| --- | --- | --- |
| 说明书文字 | 总结步骤、提取注意事项 | 说明书过长时可能遗漏细节 |
| 咖啡机照片 | 识别按钮、解释图标含义 | 看错型号或按钮位置 |
| 操作视频 | 总结操作流程、生成字幕 | 镜头没拍清时容易猜 |
| 你的语音描述 | 转成文字，再给排查建议 | 口音、噪声会影响转写 |

最稳的做法：把说明书、照片和你的问题一起给模型。材料越完整越少靠猜。

可以直接复制的 Prompt：

```text
我想学习这台咖啡机怎么用。
我会上传说明书截图和机器照片。
请你按下面格式回答：

1. 先判断机器型号和主要按钮，但不确定的地方要标注「不确定」；
2. 给出最小操作步骤，不超过 6 步；
3. 列出 3 个容易误操作的地方；
4. 如果图片看不清，不要猜，直接告诉我需要补拍哪里。
```

这个 Prompt 的重点是给模型设边界。

## 14. 使用多模态 AI 的安全边界

多模态输入常含敏感信息：身份证照片、病历截图、合同扫描件、会议录音、公司内部视频、客户聊天记录、人脸、地理位置、屏幕账号信息。NIST AI Risk Management Framework 指出要管理 AI 对个人、组织和社会带来的风险。

使用前先想五件事：

1. 这份材料能不能上传到外部平台？内部资料、客户数据等别随手丢。
2. 有没有可识别个人的信息？人脸、声音、证件号等。
3. 输出会不会被直接拿去做决策？医疗、法律、财务、人事等必须人工复核。
4. 有没有版权和肖像风险？注意人物肖像、品牌标识、音乐、影视片段。
5. 模型会不会替你执行动作？Agent 操作网页或系统时必须加确认。

版权风险：美国版权局关于生成式 AI 训练的报告讨论了 fair use 需个案判断。普通用户不要上传无权使用的素材，不要要求模仿在世艺术家独特风格，商业发布前保留授权和审核记录。

## 15. 练习题 / 小实验

练习 1：判断模态

- 把一张发票截图整理成报销表格 → 图片 + 文本
- 给一段播客生成摘要 → 语音 + 文本
- 根据一句话生成一张海报 → 文本 + 图片
- 从课程视频里提取知识点 → 视频 + 语音 + 文本

练习 2：找风险点

上传公司会议录音前，检查是否有客户信息、未公开业务数据、内部决策、个人隐私；确认公司是否允许；纪要需人工复核，尤其是待办、日期、责任人。

练习 3：设计一个多模态任务

例如电脑报错时，提供报错截图、操作步骤、系统版本和刚做过什么。

练习 4：改写一个更稳的多模态 Prompt

原Prompt “看看这张图，告诉我怎么处理。” 问题：没有说明任务、输出格式和不确定性边界。

改写：

```text
请分析这张报错截图。请按下面格式回答：
1. 先读取截图里的错误信息；
2. 判断最可能的原因，最多列 3 个；
3. 给出从低风险到高风险的排查步骤；
4. 看不清或不确定的地方请明确标注，不要猜。
```

## AI总结

本文系统介绍了多模态 AI 的核心概念：模态、编码器、常见任务流程，以及文本、图片、语音、视频四种模态各自的成熟度与风险。关键观点是：不同模态进入模型前都会转换为向量表示；从“拼接”到“原生多模态”是重要演进方向；多模态能力虽然强大，但在 OCR 小字、视频物理一致性、Agent 操作等方面仍需要人工复核。使用时应关注数据安全、版权、隐私和决策复核。
